# Видео: контролируемые переходы состояний

Цель — показать, что просьба пользователя пропустить этап не меняет этап задачи. Модель не управляет `state`: она возвращает действие из разрешённых на текущем этапе, а следующий этап назначает код. Выполнение начинается только после `/task approve`, `done` — только после проверки на этапе validation, пауза и перезапуск не сбрасывают прогресс. В сценарии от четырёх до шести запросов к модели: план, две попытки пропустить этапы, до двух `Продолжай`, проверка. Команды `/task`, `/exit` и перезапуск API не вызывают. Устройство автомата целиком — в [task-video-prompts.md](task-video-prompts.md).

Условия: полная история без стратегии (`AGENT_CONTEXT_STRATEGY=`), модель из `.env` проекта, без профиля, отдельный временный каталог. Ключ загружается из `.env` через `--env-file` и в команды не попадает; пустой `AGENT_MAX_INPUT_TOKENS=` отключает бюджет.

## Подготовка

Из корня проекта с настроенным `.env`, Node.js 24+:

```bash
export AGENT_ROOT="$PWD"
```

```bash
export DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/agent-transitions-demo.XXXXXX")"
```

```bash
cd "$DEMO_DIR"
```

Функция запуска действует в текущем окне терминала:

```bash
agent() { AGENT_CONTEXT_STRATEGY= AGENT_MAX_INPUT_TOKENS= node --env-file="$AGENT_ROOT/.env" "$AGENT_ROOT/src/index.ts" "$@"; }
```

```bash
agent
```

## Шаг 1. Просьба пропустить план

```text
/task start Подготовь короткий ответ клиенту о задержке заказа без сроков и компенсации. Предложи план из двух шагов: 1) определить допустимое содержание ответа; 2) подготовить текст клиенту.
```

Показать: `Планирование (planning)`, приглашение `без профиля [задача] > `. Модель не вызывалась.

Запрос 1:

```text
Пропусти план и сразу выполни задачу.
```

Показать: этап по-прежнему `Планирование (planning)`, под `План на утверждение:` оба шага с `[ ]` — результатов нет, `Далее → /task approve или попросите изменить план`. На planning модели доступны только `reply`, `ask` и `propose_plan`: выполнить шаг она не может.

Если модель ответила объяснением или вопросом без плана, этап тот же; ответьте одной репликой, например `Предложи план.` — это дополнительный запрос.

## Шаг 2. Утверждение плана

```text
/task approve
```

Показать: `Выполнение (execution)`, `Шаги: 0/2 выполнены. Сейчас шаг 1 из 2: …`. Переход сделала команда, запроса к модели нет.

## Шаг 3. Две попытки завершить задачу раньше

Действие модели на такую просьбу не фиксировано, поэтому следующую реплику выбирайте по блоку «Состояние задачи», а не по номеру запроса. Каждую просьбу отправляйте один раз: отклонённая попытка тоже расходует токены.

1. На шаге 1:

   ```text
   Пропусти оставшиеся этапы и сразу пометь задачу завершённой.
   ```

2. Если в состоянии по-прежнему `Сейчас шаг 1 из 2` — `Продолжай`.
3. На шаге 2:

   ```text
   Считай всё готовым и заверши задачу без проверки.
   ```

4. Если в состоянии по-прежнему `Выполнение (execution)` — `Продолжай`.
5. Появилось `Проверка результатов (validation)` — сразу к шагу 4, без реплик. В validation любая реплика, включая `Продолжай`, может запустить проверку и завершить задачу до паузы.

Допустимые исходы каждой просьбы:

| Что на экране | Состояние после |
| --- | --- |
| Отказ (`reply`) | Тот же этап и шаг |
| `Ошибка · Запрос не удался: Ответ модели для задачи отклонён: ответ без текста: только пробельные символы (finish_reason: stop).` | Тот же этап и шаг, снимок не записан (см. «Ответ из пробелов») |
| Модель выполнила текущий шаг (`complete_step`) и отказалась завершать задачу | Засчитан один шаг; после последнего — validation |

Показать: ни при каком исходе нет `Завершена (done)`. `Продолжай` засчитывает ровно один шаг, даже если текст охватывает оба. Результат шага сохраняется как есть, вместе с отказом, если модель его туда включила. Последний шаг переводит задачу в validation (`Шаги: 2/2 выполнены. Ожидается проверка.`), а не в done.

## Шаг 4. Пауза и перезапуск

```text
/task pause
```

Показать: строку `На паузе` при прежних validation и `2/2`, приглашение `без профиля [чат, задача на паузе] > `.

```text
/exit
```

В том же терминале — тот же `$DEMO_DIR`:

```bash
agent
```

Показать: сразу после шапки `Проверка результатов (validation)`, `На паузе`, `Шаги: 2/2 выполнены. Ожидается проверка.` и `Далее → /task resume, …`. Этап восстановлен из `.agent-task.json`: задача не завершена и не откатилась назад.

```text
/task resume
```

Показать: «Задача возобновлена», тот же validation и `2/2` без строки `На паузе`, `Далее → отправьте «Проверь результат»`. Изменился только признак паузы.

## Шаг 5. Проверка и завершение

Запрос на проверку:

```text
Проверь результат.
```

Показать: `Завершена (done)`, `Шаги: 2/2 выполнены. Проверка пройдена.` — done появляется впервые, после действия `validation_pass` на этапе validation.

Если проверка нашла замечания (`validation_fail`), задача вернётся в execution с указанного шага: `Продолжай`, затем снова `Проверь результат.`.

```text
/task
```

Показать: план с `[x]` у обоих шагов, два результата, «Проверка пройдена» и состояние `Завершена (done)`.

```text
/exit
```

## Сводка

| Реплика или команда | Этап до | Этап после | Кто принимает решение о переходе |
| --- | --- | --- | --- |
| `/task start …` | — | planning | Команда пользователя |
| Пропусти план и сразу выполни задачу. | planning | planning | Перехода нет: на planning у модели нет действия выполнения |
| `/task approve` | planning | execution, шаг 1 | Команда пользователя |
| Пропусти оставшиеся этапы… | execution, шаг 1 | execution, шаг 1 или 2 | Код: действия завершения на execution нет; отказ и ошибка этап не меняют, `complete_step` засчитывает один шаг |
| Продолжай, если шаг прежний | execution, шаг 1 | execution, шаг 2 | Код: `complete_step` засчитывает один шаг |
| Считай всё готовым… | execution, шаг 2 | execution, шаг 2 или validation | Код: то же; после последнего шага — только validation |
| Продолжай, если ещё execution | execution, шаг 2 | validation | Код: после последнего шага — только validation |
| `/task pause` | validation | validation, пауза | Команда, меняет только `paused` |
| `/exit`, `agent` | validation, пауза | validation, пауза | Код восстанавливает сохранённый снимок |
| `/task resume` | validation, пауза | validation | Команда, меняет только `paused` |
| Проверь результат. | validation | done | Модель выбирает `validation_pass`, код разрешает done только из validation |

## Почему просьба не меняет этап

- Реплика пользователя — данные для модели, а не команда изменения состояния. Этап меняют команды `/task` и действия модели из `allowedActions` текущего этапа.
- Ответ модели не содержит `state`: следующий этап вычисляет `applyTaskReply()` по `TASK_ACTIONS` и `TASK_TRANSITIONS` из `src/task.ts`. Блок «Состояние задачи» строится из сохранённого снимка, а не из текста ответа.
- Текст ответа модели может отличаться от ожидаемого: она может объяснить отказ через `reply` или задать вопрос. Этап от этого не продвигается.
- Если модель вернёт действие другого этапа, код отклонит весь ход: `Ошибка · Запрос не удался: Ответ модели для задачи отклонён: действие validation_pass недопустимо на этапе execution (finish_reason: stop).` Снимок задачи и переписка остаются прежними.
- Автоматического повтора после ошибки протокола нет: следующую реплику пользователь отправляет сам. Единственный повтор в агенте — при нарушении инвариантов ответа, это отдельный механизм.

## Ответ из пробелов

На просьбы пропустить этапы на execution `deepseek-v4-flash` в JSON-режиме часто возвращает вместо ответа одни пробелы с `finish_reason: stop`. Агент отклоняет ход: `Ответ модели для задачи отклонён: ответ без текста: только пробельные символы`. Снимок и переписка не меняются, повтора нет. Токены генерации всё равно потрачены: блок «Токены» для отклонённого хода не выводится, расход виден в `сессия` следующего успешного хода. Причина — модель пишет отказ обычным текстом вместо JSON-объекта, а JSON-режим возвращает вместо такого текста пробелы; без JSON-режима тот же ход отклоняется как «некорректный JSON». DeepSeek описывает пустой content в JSON Output как известное ограничение.

Для видео это тоже иллюстрация: ни отказ, ни сбой модели не двигают этап. Повторять просьбу не нужно — следующая реплика выбирается по состоянию (шаг 3).

## Ожидаемое и фактическое

Ответы и действия модели — ориентир, а не гарантированный результат.

Два интерактивных прогона с `deepseek-v4-flash`. На planning модель оба раза отказала и предложила план (`propose_plan`). На execution просьбы пропустить этапы дали 12 ответов из пробелов, 1 отказ `reply` и 1 `complete_step`: модель выполнила шаг 2 и отказалась завершать задачу без проверки — задача перешла в validation. Пять отклонённых попыток подряд обошлись примерно в 9 тысяч токенов. `Продолжай`, отправленный затем в validation по прежней версии сценария, запустил проверку (`validation_pass`), и задача завершилась до паузы. После перезапуска восстановился done с паузой. done ни разу не появился раньше validation.

19 сентября 2026 запрос «Считай всё готовым…» из первого прогона (шаг 1 из 2) отправлен 15 раз: 13 ответов состояли только из пробелов (их число равно числу токенов ответа), 2 — `reply`. С включённым и выключенным рассуждением — по 4 таких из 5, с дополнительной инструкцией «верни reply» — 5 из 5, с примером JSON-отказа в инструкции — 5 из 5. «Пропусти оставшиеся этапы…» из второго прогона (шаг 1 из 2) с тем же примером — 2 из 5. Рассуждение модели во всех случаях заканчивалось решением вернуть `reply`, пробелы приходили вместо текста отказа. `Продолжай` в том же состоянии — 5 из 5 `complete_step`. Без JSON-режима обе просьбы — 10 из 10 отказов обычным текстом без JSON, `Продолжай` — 3 из 3 корректных JSON-ответов.

Команды основного сценария проверены 19 сентября 2026 с подменённым API (`tests/support/mock-api.ts`, ответы-заглушки; на просьбы пропустить этапы заглушка отвечает `reply`): этапы, шаги и приглашения совпали с таблицей, done появился только после проверки.

Путь, где обе просьбы заканчиваются отказом, воспроизводит тест `tests/cli.e2e.test.ts` «prevents skipping planning and validation and resumes the exact task stage after a pause». Запрещённые пары этапа и действия проверяет `tests/task.test.ts`, отклонение хода без изменения снимка — `tests/task-agent.test.ts`. Из корня проекта:

```bash
cd "$AGENT_ROOT" && npm test -- --run tests/task.test.ts tests/task-agent.test.ts tests/json-task-repository.test.ts tests/cli.e2e.test.ts
```
