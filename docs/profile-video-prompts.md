# Видео: профили агента с общей памятью

Цель — показать, что ручное переключение профиля меняет роль и инструкции следующего ответа, а разговор, рабочая память и статистика остаются общими. Один агент готовит анонс мероприятия ролями «аналитик», «автор» и «редактор»; после перезапуска восстанавливается выбранный профиль. В основной части четыре запроса к модели без активной задачи автомата; `/profile list`, `/profile`, `/profile load`, `/memory set` и `/exit` API не вызывают.

Условия: полная история без стратегии (`AGENT_CONTEXT_STRATEGY=`), prompting `direct` (значение по умолчанию), модель из `.env` проекта, отдельный временный каталог. Ключ загружается из `.env` через `--env-file` и в команды не попадает. Переменные, заданные в команде запуска, важнее значений из `.env`; пустой `AGENT_MAX_INPUT_TOKENS=` отключает бюджет.

Профили заранее загружаются из [agent-profiles.demo.json](agent-profiles.demo.json), чтобы видео не занимал опрос `/profile-init`. Активный профиль в примере — `аналитик`.

## Подготовка

Из корня проекта с настроенным `.env`, Node.js 24+:

```bash
export AGENT_ROOT="$PWD"
```

```bash
export DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/agent-profile-demo.XXXXXX")"
```

```bash
cp "$AGENT_ROOT/docs/agent-profiles.demo.json" "$DEMO_DIR/.agent-profiles.json"
```

```bash
cd "$DEMO_DIR"
```

Функция запуска действует в текущем окне терминала:

```bash
agent() { AGENT_CONTEXT_STRATEGY= AGENT_MAX_INPUT_TOKENS= node --env-file="$AGENT_ROOT/.env" "$AGENT_ROOT/src/index.ts" "$@"; }
```

```bash
agent
```

Показать: `Профиль: аналитик`, приглашение `аналитик > `.

```text
/profile list
```

Заранее подготовленные профили

```text
/profile-init
```

Начать процесс создания нового профиля

```text
автор
```

Идентификатор профиля

```text
Живой дружелюбный текст анонса до 120 слов: заголовок, основной текст, призыв к действию
```

Style

```text
Следуй согласованному брифу. Не добавляй дату, ссылку, спикеров и другие неподтверждённые факты; вместо них оставь пометку [уточнить]
```

Constraints

```text
Ты автор анонсов мероприятий. Пишешь текст для публикации по согласованному брифу
```

Context

```text
/profile load аналитик
```

Переключиться на профиль - аналитик

```text
/profile list
```

Показать: три профиля — `автор`, `аналитик` с пометкой `* … — активный`, `редактор`.

Общий факт записывается один раз в рабочую память:

```text
/memory set working event Бесплатная онлайн-встреча «Первый агент», 40 минут, для новичков.
```

## Шаг 1. Аналитик

```text
/profile
```

Показать: роль, ограничения и стиль аналитика.

Запрос 1:

```text
Составь краткий бриф и предложи структуру анонса.
```

Ожидается: бриф пунктами и структура анонса, без готового текста; недостающие сведения (дата, ссылка) перечислены отдельно, а не придуманы.

## Шаг 2. Автор

```text
/profile load автор
```

Показать: `Профиль: автор`, приглашение `автор > `. Модель не вызывалась.

Запрос 2:

```text
Подготовь анонс по согласованному брифу.
```

Ожидается: готовый текст анонса по брифу аналитика из общей истории; формат, длительность и аудитория из working; вместо неизвестной даты и ссылки — `[уточнить]`. Строка `Ход · сессия` продолжает статистику первого запроса.

## Шаг 3. Редактор

```text
/profile load редактор
```

Запрос 3:

```text
Проверь подготовленный анонс. Назови конкретные недочёты; если их нет — так и скажи.
```

Ожидается: короткий список замечаний к тексту автора со сверкой с брифом, без новых фактов; при отсутствии недочётов — прямое сообщение об этом.

## Шаг 4. Перезапуск

```text
/exit
```

В том же терминале — тот же `$DEMO_DIR`:

```bash
agent
```

Показать: сразу `Профиль: редактор` и приглашение `редактор > `.

Запрос 4:

```text
Назови формат, длительность и аудиторию мероприятия, затем напомни результат последней проверки.
```

Ожидается: онлайн-встреча, 40 минут, для новичков — из working; краткий пересказ замечаний шага 3 из общей истории. Статистика начинается заново: `Ход` равен `сессии`.

```text
/exit
```

## Сводка

| Запрос | Профиль | Что есть в запросе | Ожидаемое поведение |
| --- | --- | --- | --- |
| 1 | аналитик | working | бриф и структура, без текста анонса |
| 2 | автор | working, ход 1 | текст анонса по брифу, `[уточнить]` вместо неизвестного |
| 3 | редактор | working, ходы 1–2 | конкретные замечания или «недочётов нет» |
| 4 | редактор после перезапуска | working, ходы 1–3 | формат, длительность, аудитория и итог проверки |

Для наглядности хранения можно показать файлы, API они не вызывают:

```bash
cat "$DEMO_DIR/.agent-profiles.json"
```

```bash
ls -a "$DEMO_DIR"
```

В каталоге один файл истории и один файл working для всех профилей; `.agent-users/` нет.

## Ожидаемое и фактическое

Колонка «Ожидаемое поведение» — ожидание, а не зафиксированный ответ: модель может нарушить роль или оформление.

Точную последовательность команд этого сценария воспроизводит e2e-тест `tests/cli.e2e.test.ts` («replays the profile video script…») на профилях из `agent-profiles.demo.json` и подменённом API (`tests/support/mock-api.ts`, эхо-ответы). Тест проверяет состав каждого из четырёх запросов — блок активного профиля, working и предыдущие ходы — и состояние: список профилей, приглашения, продолжение статистики до перезапуска и новую после него, один `.agent-history.json` с четырьмя парами, `.agent-profiles.json` с `activeProfileId: "редактор"` и отсутствие других файлов. Сборку запросов и сессию отдельно покрывают `tests/profile-requests.test.ts`, `tests/session.test.ts`, `tests/cli.test.ts`.

Поведение реальной модели не проверено: прогон с ней не выполнялся, фактические ответы фиксируются после записи видео.
