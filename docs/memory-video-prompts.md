# Видео: три слоя памяти

Цель — показать, куда агент кладёт сведения, сколько они живут и как влияют на ответ. В сценарии пять запросов к модели, если ни один ответ не отклонён проверкой инвариантов; команды `/memory`, `/reset` и `/exit` API не вызывают.

Условия: Sliding Window, `AGENT_KEEP_LAST_MESSAGES=2`, prompting `direct` (значение по умолчанию), модель из `.env` проекта, отдельный временный каталог. Ключ загружается из `.env` через `--env-file` и в команды не попадает. Переменные, заданные в команде запуска, важнее значений из `.env`; пустой `AGENT_MAX_INPUT_TOKENS=` отключает бюджет, если он задан в `.env`.

## Подготовка

Из корня проекта с настроенным `.env`, Node.js 24+:

```bash
export AGENT_ROOT="$PWD"
```

```bash
export DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/agent-memory-demo.XXXXXX")"
```

```bash
cd "$DEMO_DIR"
```

Функция запуска действует в текущем окне терминала:

```bash
agent() { AGENT_CONTEXT_STRATEGY=sliding AGENT_KEEP_LAST_MESSAGES=2 AGENT_MAX_INPUT_TOKENS= node --env-file="$AGENT_ROOT/.env" "$AGENT_ROOT/src/index.ts" "$@"; }
```

## Шаг 1. Записать память и назвать код разговора

```bash
agent
```

Команды в CLI, по одной строке:

```text
/memory set working goal поездка в Казань
```

```text
/memory set working budget 30000 рублей
```

```text
/memory set long transport предпочитаю поезд
```

Запрос 1:

```text
Код текущего разговора — КЕДР. Ответь только “Принято”.
```

```text
/memory
```

Показать на экране: код КЕДР есть только в `short` (пара вопрос/ответ), `working` содержит `goal` и `budget`, `long` — `transport`.

## Шаг 2. Контрольный вопрос: все три слоя

Запрос 2:

```text
Назови цель, бюджет, предпочтительный транспорт и код разговора. Неизвестное обозначь “не знаю”.
```

Ожидается: поездка в Казань, 30000 рублей, поезд, КЕДР. Окно из двух сообщений ещё содержит ход с кодом.

## Шаг 3. Сброс диалога и перезапуск

```text
/reset
```

```text
/exit
```

В том же терминале — тот же `$DEMO_DIR`:

```bash
agent
```

```text
/memory
```

Показать: `short` пустой, `working` и `long` восстановлены из файлов каталога.

Запрос 3:

```text
Назови цель, бюджет, предпочтительный транспорт и код разговора. Неизвестное обозначь “не знаю”.
```

Ожидается: цель, бюджет и транспорт названы, код — «не знаю».

## Шаг 4. Новая задача: очистить рабочую память

Ответ шага 3 повторил цель и бюджет, поэтому после очистки словаря сбрасывается и диалог.

```text
/memory clear working
```

```text
/reset
```

Запрос 4:

```text
Назови цель, бюджет, предпочтительный транспорт и код разговора. Неизвестное обозначь “не знаю”.
```

Ожидается: известен только предпочтительный транспорт.

## Шаг 5. Удалить предпочтение из долговременной памяти

```text
/memory delete long transport
```

```text
/reset
```

```text
/memory
```

Показать: все три слоя пустые.

Запрос 5:

```text
Назови цель, бюджет, предпочтительный транспорт и код разговора. Неизвестное обозначь “не знаю”.
```

Ожидается: «не знаю» по всем четырём пунктам.

```text
/exit
```

## Сводка

| Шаг | short перед запросом | working | long | Ожидаемый ответ |
| --- | --- | --- | --- | --- |
| 1 | пусто | goal, budget | transport | «Принято» |
| 2 | ход с КЕДР | goal, budget | transport | цель, бюджет, поезд, КЕДР |
| 3 | пусто после `/reset` и перезапуска | goal, budget | transport | цель, бюджет, поезд; код неизвестен |
| 4 | пусто | пусто | transport | только поезд |
| 5 | пусто | пусто | пусто | всё неизвестно |

Оценка «весь стек» в выводе CLI уменьшается по мере очистки слоёв: блоки памяти входят в запрос.

## Ожидаемое и фактическое

Таблица описывает ожидаемое поведение модели, а не гарантированный текст. Модель может перефразировать ответ, пропустить пункт или назвать сведения из общих знаний. Детерминированно проверяются содержимое слоёв (`/memory`) и состав запросов в автотестах: `tests/memory.test.ts`, `tests/cli.e2e.test.ts`.

Прогон с реальной моделью при подготовке сценария не выполнялся; фактические ответы фиксируются после записи видео. Команды и последовательность шагов проверены 14 сентября 2026 с подменённым API (`tests/support/mock-api.ts`): содержимое слоёв после каждого шага совпало с таблицей.
