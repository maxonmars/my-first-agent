# Видео: задача как конечный автомат

Цель — показать, что агент ведёт задачу по этапам `planning → execution → validation → done`, сохраняет прогресс, отпускает реплики в обычный чат на паузе и после перезапуска продолжает с сохранённого места без повторного объяснения. В основном сценарии пять запросов к модели: план, первый шаг, обычный чат, второй шаг, проверка; ещё один — на каждый ответ, отклонённый проверкой инвариантов (см. README, «Инварианты ответа»). Команды `/task`, `/exit` и перезапуск API не вызывают.

Условия: полная история без стратегии (`AGENT_CONTEXT_STRATEGY=`), prompting `direct` (значение по умолчанию), модель из `.env` проекта, без профиля, отдельный временный каталог. Ключ загружается из `.env` через `--env-file` и в команды не попадает; пустой `AGENT_MAX_INPUT_TOKENS=` отключает бюджет.

## Подготовка

Из корня проекта с настроенным `.env`, Node.js 24+:

```bash
export AGENT_ROOT="$PWD"
```

```bash
export DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/agent-task-demo.XXXXXX")"
```

```bash
cd "$DEMO_DIR"
```

Функция запуска действует в текущем окне терминала:

```bash
agent() { AGENT_CONTEXT_STRATEGY= AGENT_MAX_INPUT_TOKENS= node --env-file="$AGENT_ROOT/.env" "$AGENT_ROOT/src/index.ts" "$@"; }
```

```bash
agent
```

Показать: короткую шапку со строкой `Команды: /help · /task · /memory · /profile · /invariants` и приглашение `без профиля > ` — задачи нет. Команды задачи — в группе «Задача» справки `/help`.

## Шаг 1. Создать задачу и получить план

```text
/task start Подготовь короткий ответ клиенту, который жалуется на задержку заказа. Новая дата доставки неизвестна, компенсация не согласована: не называй сроков и не обещай компенсацию. Предложи план из двух шагов: 1) определить допустимое содержание ответа; 2) подготовить текст клиенту.
```

Показать: «Задача создана», блок «Состояние задачи» с `Планирование (planning)` и `Далее → уточните условия или попросите составить план`, приглашение `без профиля [задача] > `. Модель ещё не вызывалась.

Запрос 1:

```text
Продолжай
```

Ожидается: блок «Ответ агента» с коротким ответом, блок «Токены», затем «Состояние задачи»: сохранённый план из двух шагов под заголовком `План на утверждение:` и `Далее → /task approve или попросите изменить план`. Шаги берутся из состояния задачи, даже если в тексте ответа модели их нет.

Если модель вместо плана задала вопрос (`Далее → ответьте на вопрос агента`), ответьте одной репликой — это дополнительный запрос:

```text
Имя клиента и номер заказа неизвестны, используй нейтральное обращение. Предложи план.
```

## Шаг 2. Утвердить план и выполнить первый шаг

```text
/task approve
```

Показать: `Выполнение (execution)` и `Сейчас шаг 1 из 2: …`. Запроса к модели нет.

Запрос 2:

```text
Продолжай
```

Ожидается: результат только первого шага — что можно и чего нельзя писать клиенту; в состоянии `Шаги: 1/2 выполнены. Сейчас шаг 2 из 2: …`.

## Шаг 3. Пауза и обычный чат

```text
/task pause
```

Показать: «Реплики идут в обычный чат», строку `На паузе` в состоянии и приглашение `без профиля [чат, задача на паузе] > `.

Запрос 3:

```text
Как по-английски «задержка доставки»? Ответь одной фразой.
```

Ожидается: обычный ответ без блока «Состояние задачи»; реплика не попадает в переписку задачи.

## Шаг 4. Перезапуск

```text
/exit
```

В том же терминале — тот же `$DEMO_DIR`:

```bash
agent
```

Показать: в начале вывода, после шапки, `Выполнение (execution)`, `На паузе`, `Сейчас шаг 2 из 2: …` и `Далее → /task resume, …`.

```text
/task resume
```

Показать: «Задача возобновлена. Реплики снова идут в задачу.», приглашение `без профиля [задача] > `.

## Шаг 5. Второй шаг без повторного объяснения

Запрос 4:

```text
Продолжай
```

Ожидается: короткий текст клиенту без сроков и компенсации; состояние `Проверка результатов (validation)` и `Далее → отправьте «Проверь результат»`. Проверка в этом же ходе не запускается.

## Шаг 6. Проверка и завершение

Запрос 5:

```text
Проверь результат
```

Ожидается: подтверждение, что сроков и обещаний компенсации нет; состояние `Завершена (done)`.

```text
/task
```

Показать: блоки описания, плана с `[x]` у обоих шагов, полных результатов, проверки «Проверка пройдена» и состояния задачи.

Если проверка нашла замечания, этап вернётся к `execution` с шага из замечаний. Тогда ещё по одной реплике: `Продолжай`, затем `Проверь результат`.

```text
/exit
```

## Сводка

| Запрос | Реплика | Этап до | Этап после | Действие модели |
| --- | --- | --- | --- | --- |
| 1 | Продолжай | planning | planning | `propose_plan` |
| — | `/task approve` | planning | execution | команда, без модели |
| 2 | Продолжай | execution, шаг 1 | execution, шаг 2 | `complete_step` |
| — | `/task pause` | execution | execution, пауза | команда, без модели |
| 3 | вопрос в чат | обычный чат | обычный чат | обычный ответ |
| — | перезапуск, `/task resume` | execution, пауза | execution | команда, без модели |
| 4 | Продолжай | execution, шаг 2 | validation | `complete_step` |
| 5 | Проверь результат | validation | done | `validation_pass` |

Для наглядности хранения можно показать файл, API он не вызывает:

```bash
cat "$DEMO_DIR/.agent-task.json"
```

## Короткие дополнения

Пауза на planning — после запроса 1, вместо шага 2:

```text
/task pause
```

`/exit`, `agent`: в состоянии `Планирование (planning)` со строкой `На паузе` снова выведен `План на утверждение:`; после `/task resume` — тоже. Затем `/task approve` — выполнение начинается с шага 1.

Если при перезапуске у задачи есть открытый вопрос, он выводится строкой `Вопрос агента: …` при запуске и после `/task resume`, без запроса к модели.

Пауза на validation — после запроса 4: `/task pause`, `/exit`, `agent`, `/task resume`. Состояние `Проверка результатов (validation)`; следующая реплика `Проверь результат` запускает проверку.

Пауза и обсуждение в done — после запроса 5:

```text
/task pause
```

`/task resume`, затем реплика — ещё один запрос:

```text
Можно ли отправить этот текст клиенту без правок?
```

Ожидается: ответ по результату, этап остаётся `done`. Завершённую задачу можно заменить командой `/task start …` или удалить `/task clear`; `/reset` задачу не удаляет.

## Ожидаемое и фактическое

Ожидаемые ответы и действия модели в таблицах — ориентир, а не гарантированный результат: модель может задать уточняющий вопрос, перефразировать план или найти замечания при проверке. Переходы, проверка протокола, сохранение и восстановление каждого этапа проверяются автотестами без реального API: `tests/task.test.ts`, `tests/task-agent.test.ts`, `tests/json-task-repository.test.ts`, `tests/session.test.ts`, `tests/cli.test.ts`, `tests/cli.e2e.test.ts`.

Прогон с реальной моделью при подготовке сценария не выполнялся; фактические ответы фиксируются после записи видео. Команды основного сценария и дополнений проверены 17 сентября 2026 с подменённым API (`tests/support/mock-api.ts`, ответы-заглушки вместо текста модели): этапы, статусы, приглашения и число вызовов модели совпали с таблицей; после паузы `.agent-task.json` содержал этап execution, результат первого шага и `paused: true`.
