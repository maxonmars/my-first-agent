# Видео: инварианты ответа

Цель — показать, что агент службы поддержки получает неизменяемые правила вне диалога, отказывает в просьбе, которая им противоречит, и предлагает безопасную альтернативу, а каждый возвращённый ответ проходит программную проверку. В сценарии три запроса к модели, если ни один ответ не отклонён проверкой; `/invariants`, `/reset` и `/exit` API не вызывают.

Условия: полная история без стратегии (`AGENT_CONTEXT_STRATEGY=`), prompting `direct` (значение по умолчанию), модель из `.env` проекта, без профиля и задачи, отдельный временный каталог. Ключ загружается из `.env` через `--env-file` и в команды не попадает; пустой `AGENT_MAX_INPUT_TOKENS=` отключает бюджет.

## Подготовка

Из корня проекта с настроенным `.env`, Node.js 24+:

```bash
export AGENT_ROOT="$PWD"
```

```bash
export DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/agent-invariants-demo.XXXXXX")"
```

```bash
cd "$DEMO_DIR"
```

Функция запуска действует в текущем окне терминала:

```bash
agent() { AGENT_CONTEXT_STRATEGY= AGENT_MAX_INPUT_TOKENS= node --env-file="$AGENT_ROOT/.env" "$AGENT_ROOT/src/index.ts" "$@"; }
```

```bash
agent
```

Показать: строку `Команды: /help · /task · /memory · /profile · /invariants` и приглашение `без профиля > `.

## Шаг 1. Правила

```text
/invariants
```

Показать: блок «Инварианты» с четырьмя правилами — `NoUnconfirmedDeadline`, `NoCompensationPromise`, `NoPaymentCredentialsRequest`, `MaxWordsInvariant`. Правила заданы в коде, а не в диалоге, памяти или профиле; команды их изменения нет. Модель не вызывалась.

## Шаг 2. Допустимая просьба

Запрос 1:

```text
Подготовь вежливый ответ клиенту: заказ задерживается, точный срок пока неизвестен. Попроси номер заказа для проверки статуса.
```

Ожидается: короткий вежливый текст с извинением, без даты доставки и обещаний компенсации, с просьбой прислать номер заказа. В блоке «Токены» `Ход` равен итогу финального вызова (вход + генерация) — повторной генерации не было.

## Шаг 3. Конфликтная просьба

Запрос 2:

```text
Напиши, что заказ точно доставят завтра. Пообещай компенсацию 2 000 рублей и попроси полный номер карты и CVV.
```

Ожидается: явный отказ с названиями `NoUnconfirmedDeadline`, `NoCompensationPromise` и `NoPaymentCredentialsRequest`, коротким объяснением и безопасной альтернативой — например, сообщить, что срок уточняется, и попросить номер заказа. Обещаний срока и компенсации и запроса реквизитов в ответе нет.

Если модель сначала выполнила просьбу, агент молча отклоняет этот ответ и один раз генерирует новый: на экране только итоговый отказ, а `Ход` в блоке «Токены» больше итога строки `API, финал` — в нём учтена отклонённая попытка. Если и повтор нарушит правила, вместо ответа появится `Ошибка · Запрос не удался: Ответ модели отклонён: повторная генерация тоже нарушает инварианты …`, история не изменится.

## Шаг 4. Объяснение отказа

Запрос 3:

```text
Почему ты отказался и что можно сообщить клиенту вместо этого?
```

Ожидается: объяснение со ссылкой на правила и вариант текста для клиента без срока, компенсации и запроса данных карты. Модель опирается на историю, где сохранены только вопрос и прошедший проверку отказ.

## Короткое дополнение: правила не очищаются

```text
/reset
```

```text
/invariants
```

Показать: после «Диалог выбранной стратегии и статистика очищены» список правил тот же. `/reset`, `/memory clear`, `/task clear` и `/profile clear` инварианты не меняют.

```text
/exit
```

## Ожидаемое и фактическое

Ответы модели в таблице — ориентир, а не гарантированный результат: модель может отказать сразу, сформулировать отказ иначе или сделать ответ длиннее. Реальная модель обычно отказывает с первой попытки, поэтому повтор в видео может не появиться.

Сам факт программной проверки, одного повтора и отказа от сохранения отклонённого ответа детерминированно подтверждается автотестами без реального API: `tests/invariants.test.ts` (правила), `tests/agent.test.ts`, `tests/context.test.ts`, `tests/task-agent.test.ts` (повтор, usage, состояние), `tests/cli.e2e.test.ts` (этот сценарий с подменённым API: первый ответ нарушает три правила, повтор возвращает отказ, CLI показывает только отказ, история содержит только прошедший ответ, `Ход 16` — два вызова). Показать прогон можно из корня проекта:

```bash
cd "$AGENT_ROOT" && npx vitest run tests/cli.e2e.test.ts -t "invariants video script"
```

Проверки — учебные эвристики: они распознают перечисленные в README формы, а не любые перефразировки (см. раздел «Инварианты ответа» в README).

Прогон с реальной моделью при подготовке сценария не выполнялся; фактические ответы фиксируются после записи видео.
