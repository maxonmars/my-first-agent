# my-first-agent

Stateful CLI-агент для диалога с DeepSeek через OpenAI-совместимый API.

Агент — отдельная сущность: он хранит конфигурацию и историю сообщений, формирует запросы к LLM, проверяет ответы и считает токены. CLI отвечает только за пользовательский ввод и отображение `AgentResult`.

```text
CLI → Agent → OpenAI SDK → DeepSeek API
```

## Подготовка

Нужен Node.js 24+.

```bash
npm install
cp .env.example .env
```

Добавьте ключ в `.env`:

```dotenv
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-v4-flash
```

`.env` исключён из Git.

## Запуск

Один запрос:

```bash
npm run dev -- "Почему небо синее?"
```

Интерактивный диалог с общей историей:

```bash
npm run dev
```

Команды интерактивного режима:

- `/reset` — сохранить `{ summary: null, messages: [] }` в файл истории, затем очистить историю и статистику агента;
- `/exit` — завершить диалог.

После каждого ответа CLI показывает оценки нового вопроса и входного стека, usage summary (если выполнено), финального вызова и расход хода и сессии.

## Работа с токенами

`tokenEstimate.questionTokens` — оценка только нового вопроса после `trim()`. `tokenEstimate.contextTokens` — оценка всего стека перед финальным вызовом: system + summary (если есть) + несжатая история + новый вопрос. В system входят инструкции стратегии, формата и ограничения; для meta — также полученная подготовительным вызовом инструкция. Генерируемого ответа в этом стеке ещё нет.

`src/tokens.ts` оценивает текст как `Math.ceil(text.length / 4)` и складывает оценки `content` сообщений без служебных надбавок. Это грубая эвристика по длине JavaScript-строки, а не токенизатор DeepSeek; ошибка зависит от языка и содержимого. В CLI локальные оценки отмечены `≈`.

`usage.finalCall` содержит provider usage финального вызова: вход и генерацию ответа. `completionTokens` может включать рассуждения; `reasoningTokens` показывается как её часть и повторно к итогу не прибавляется. `usage.summaryCall` содержит расход сжатия или `null`, если его не было. `usage.turn` суммирует summary + подготовку meta + финальный вызов, `usage.session` — вызовы текущего процесса. Локальные оценки не заменяют usage; при его отсутствии сохраняется нулевой fallback.

Накопленный расход не равен размеру стека: история повторно отправляется на каждом вызове. После перезапуска summary и сообщения восстанавливаются, а расход сессии начинается с нуля.

Учебный лимит включается в `.env` или окружении:

```dotenv
AGENT_MAX_INPUT_TOKENS=2000
```

Пустое или отсутствующее значение отключает ограничение (`maxInputTokens: null`). Указанное значение должно быть положительным безопасным целым числом. Прямое создание `Agent` проверяет это же условие.

Это локальный бюджет оценочного входа, а не реальное контекстное окно DeepSeek: он не резервирует будущую генерацию и не гарантирует принятия запроса провайдером. `maxTokens` по-прежнему передаётся как `max_tokens` и ограничивает генерацию; `maxInputTokens` в API не передаётся.

Перед каждым API-вызовом, включая summary и оба вызова meta, агент сравнивает фактический подготовленный стек с бюджетом. Равенство разрешено. При превышении `AgentContextLimitError` указывает стадию; для summary предлагает увеличить бюджет или выполнить `/reset`, для остальных вызовов — сократить вопрос или выполнить `/reset`. Заблокированный вызов не происходит, новая пара не сохраняется. Уже потраченный расход summary и подготовки meta остаётся в сессии. Однократный CLI возвращает код `1`, интерактивный принимает следующий ввод. Успешный `/reset` очищает историю и статистику, сохраняя лимит.

При `finishReason === "length"` CLI предупреждает об остановке генерации по лимиту длины: ответ может быть неполным. Это не доказательство переполнения входного контекста. Непустой усечённый ответ возвращается и сохраняется.

Тестовый сценарий сравнивает короткий диалог (2 хода), длинный (8 ходов) и локальный отказ. С вопросом и ответом по 4 символа оценка вопроса остаётся ≈1, стек растёт от ≈2 до ≈16; следующий стек ≈18 превышает бюджет 16 и не вызывает клиент. После `/reset` стек снова ≈2. Фиксированный mock usage — 8 токенов на ход, 64 за восемь ходов — служит тестовыми данными, а не измерением DeepSeek.

## История между запусками

CLI сохраняет завершённые пары `user` / `assistant` в `.agent-history.json` в текущей рабочей директории приложения (`process.cwd()`). При следующем запуске история загружается автоматически. Интерактивный режим и один запрос используют общий файл; у запусков из разных директорий отдельные истории.

Файл содержит объект `{ "summary": null, "messages": [] }`: summary — `null` или непустая строка, messages — завершённые пары с полями `role` и `content`. Старый JSON-массив читается как messages с summary=null без перезаписи файла. Следующий успешный save записывает объект. Системный промпт, внутренние сообщения meta-стратегии, конфигурация, API-ключ и статистика в него не записываются. После перезапуска статистика токенов начинается с нуля.

Каждый завершённый ход сохраняется до вывода ответа: сначала во временный файл `.agent-history.json.<UUID>.tmp` рядом с основным, затем основной файл заменяется через `renameSync`. Выход через `/exit` для сохранения не требуется. `/reset` записывает `{ summary: null, messages: [] }`, не удаляя файл. При ошибке сброса summary, история и статистика в памяти остаются прежними.

Отсутствующий файл означает пустую историю. Повреждённый JSON, неверная структура или ошибка чтения останавливают запуск с ненулевым кодом; сообщение содержит причину и путь к файлу. Перед новым стартом исправьте файл или переместите его в резервную копию. Автоматического восстановления, удаления или перезаписи повреждённой истории нет.

При ошибке сохранения полученный ответ не считается успешным, кандидат summary и новая пара не попадают в память, предыдущий файл сохраняется. Потраченные токены учитываются. Однократный режим завершается с кодом `1`, интерактивный сообщает об ошибке и принимает следующий ввод.

Один пишущий процесс на файл: атомарная замена не решает конфликт одновременно работающих CLI. История загружается целиком. Summary может потерять детали; полного архива для их восстановления нет. Нет разбиения слишком длинной суммаризации, автоматического восстановления, поиска, SQLite, версий формата, блокировок и сохранения usage.

### Периодическое сжатие

По умолчанию включено:

```dotenv
AGENT_HISTORY_COMPRESSION=true
AGENT_KEEP_LAST_MESSAGES=10
```

`AGENT_HISTORY_COMPRESSION=false` запрещает новые сжатия. Уже сохранённое summary продолжает использоваться: удалённые сообщения не восстанавливаются. Пустые или отсутствующие значения используют defaults; неверные непустые значения вызывают ошибку. N — положительное чётное безопасное целое, проверяется также при прямом создании Agent. N=10 означает пять пар user/assistant.

Перед новым вопросом агент проверяет только сохранённые сообщения: при количестве ≥ N+10 весь префикс кроме последних N заменяется новым summary. Порция накопления фиксирована: 10 сообщений. При N=10 после 10 ходов есть 20 сообщений, перед 11-м вопросом сжимаются первые 10, после ответа остаются summary и 12 сообщений. Следующее сжатие — перед 16-м вопросом. Между сжатиями хвост может превышать N. Длинная загруженная история сжимается одним вызовом по тому же правилу.

Служебный запрос использует ту же модель, прежнее summary и вытесняемый префикс с ролями. Хвост и новый вопрос туда не входят. `max_tokens=512`, thinking выключен; формат, stop-маркер, maxWords/maxTokens финального ответа и meta к summary не применяются. Новое summary заменяет прежнее. Пустое или усечённое summary — ошибка сжатия, usage такого ответа учитывается.

Стек запроса: системные инструкции → явно обозначенное summary как данные о прошлом в user-сообщении → хвост → вопрос. Summary не добавляется в system. Meta и финальный ответ используют одно подготовленное состояние. Кандидат сохраняется вместе с новой парой одним save; память обновляется после успеха. Ошибка summary, meta, финального ответа или save оставляет прежнее состояние, учитывает полученный usage и освобождает busy. Автоматического повтора хода нет. Непустой усечённый или не прошедший валидацию **финальный ответ** по-прежнему сохраняется.

### Ручная проверка с моделью

Нужны настроенный ключ в `.env` и доступ к API. Из корня проекта создайте отдельную временную директорию, чтобы сохранить пользовательскую историю:

```bash
agent_project_dir="$PWD"
agent_check_dir="$(mktemp -d)"
(
  cd "$agent_check_dir"
  node --env-file="$agent_project_dir/.env" "$agent_project_dir/src/index.ts"
)
```

Введите `Запомни кодовую фразу: медный барсук 731`, дождитесь ответа и завершите диалог через `/exit`. Запустите отдельный процесс с той же тестовой историей:

```bash
(
  cd "$agent_check_dir"
  node --env-file="$agent_project_dir/.env" "$agent_project_dir/src/index.ts" "Какую кодовую фразу я попросил запомнить?"
)
```

Проверьте, что ответ содержит кодовую фразу, а расход сессии учитывает только новый запрос. Повторите интерактивный запуск из первого блока без повторного создания директории, выполните `/reset` и `/exit`. В `$agent_check_dir/.agent-history.json` должен остаться `{ "summary": null, "messages": [] }`; повторный запуск с вопросом больше не должен получать прежний контекст.

### Воспроизведение

Из корня проекта с настроенным `.env` выполните блок ниже (Node.js 24+). Он создаёт одноразовый скрипт и два независимых каталога с чистой историей во временной директории. Пользовательская `.agent-history.json` не используется. Модель берётся из настроек; системный промпт, direct/text, температура 0, thinking disabled и отсутствие лимитов одинаковы. Локальный бюджет отключён, чтобы не блокировать baseline. Не переключайте baseline на уже сжатой истории.

```bash
agent_compare_script="$(mktemp -t agent-compare).mjs"
cat > "$agent_compare_script" <<'JS'
import { mkdtempSync, writeFileSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { pathToFileURL } from 'node:url';
const project = process.cwd();
const { Agent } = await import(pathToFileURL(join(project, 'src/agent.ts')));
const { readConfig, DEEPSEEK_BASE_URL } = await import(pathToFileURL(join(project, 'src/config.ts')));
const { JsonHistoryRepository } = await import(pathToFileURL(join(project, 'src/json-history-repository.ts')));
const { default: OpenAI } = await import(pathToFileURL(join(project, 'node_modules/openai/index.mjs')));
const questions = [
  'Планируем проект «Север». Идентификатор SN-047, город Томск. Запомни эти данные.',
  'Бюджет проекта 84000 рублей. Дата запуска 17 октября 2026 года. Запомни.',
  'Координатор — Ирина Белова. Код доступа к учебному макету: кедр-731. Это вымышленные данные.',
  'Ограничение: не предлагай платные облачные сервисы; все данные храним локально. Подтверди.',
  'Критерий готовности — 12 успешно обработанных заявок. Открытый вопрос: кто проведёт приёмку?',
  'Исправление: бюджет теперь 96000 рублей вместо 84000. Остальные условия прежние. Запомни.',
  'Объясни одним предложением, чем очередь отличается от стека.',
  'Предложи два коротких названия для тестового файла, не меняя название проекта.',
  'Как отличить ошибку ввода от ошибки сети? Ответь кратко.',
  'Для ближайшего теста используем кабинет 314 и набор данных trial-B9. Запомни.',
  'Контроль: назови проект, идентификатор, город, актуальный бюджет, дату, координатора, код макета, критерий готовности и нерешённый вопрос. Какие способы хранения и сервисы допустимы?',
  'Контроль недавних деталей: какой кабинет и набор данных выбраны для ближайшего теста?',
  'Решение: приёмку проведёт Павел Орлов. Это закрывает прежний открытый вопрос. Запомни.',
  'Объясни одним предложением, зачем нужны резервные копии.',
  'Новая деталь теста: старт в 09:40, ответственный за тест — Антон. Запомни.',
  'Контроль: повтори проект, идентификатор, город, актуальный бюджет, дату, координатора, код макета, критерий готовности и кто проведёт приёмку. Предложи способ хранения с учётом моего ограничения.',
  'Контроль недавних деталей: время старта, ответственный за тест, кабинет и набор данных?',
  'Назови два преимущества коротких сообщений об ошибках.',
  'Предложи краткий следующий шаг для проекта с учётом ограничений.',
  'Итоговый контроль: перечисли основные факты проекта, актуальный бюджет, кто проводит приёмку и параметры ближайшего теста. Соблюдай ограничение на сервисы и хранение.',
];
const app = readConfig();
const output = mkdtempSync(join(tmpdir(), 'agent-comparison-'));
console.log('RESULT_DIR', output);
const runs = [];
for (const enabled of [false, true]) {
  const directory = mkdtempSync(join(output, enabled ? 'B-' : 'A-'));
  const sdk = new OpenAI({ apiKey: app.apiKey, baseURL: DEEPSEEK_BASE_URL, maxRetries: 0, timeout: 45000 });
  const rawUsage = [];
  const client = { async create(params) {
    const response = await sdk.chat.completions.create(params);
    rawUsage.push(response.usage ?? null);
    return response;
  } };
  const config = { ...app.agent, strategy: 'direct', format: 'text', temperature: 0, thinkingEnabled: false,
    systemPrompt: 'Ты полезный ассистент. Отвечай кратко и по делу.', maxWords: null, maxTokens: null,
    stopMarker: null, maxInputTokens: null, historyCompressionEnabled: enabled, historyKeepLastMessages: 10 };
  const agent = new Agent({ client, config, historyRepository: new JsonHistoryRepository(join(directory, '.agent-history.json')) });
  const results = [];
  try {
    for (const [i, question] of questions.entries()) {
      const result = await agent.respond(question);
      results.push({ turn: i + 1, question, ...result });
      console.log(enabled ? 'B' : 'A', i + 1, result.usage.turn.totalTokens);
      writeFileSync(join(directory, 'results.json'), JSON.stringify({ config, results, rawUsage }, null, 2));
    }
  } catch (error) {
    console.log('RUN_FAILED', enabled ? 'B' : 'A', error.name, error.status ?? '', error.message);
    writeFileSync(join(directory, 'results.json'), JSON.stringify({ config, results, rawUsage, failure: { name: error.name, status: error.status, message: error.message } }, null, 2));
    process.exitCode = 1;
    break;
  }
  runs.push({ mode: enabled ? 'B' : 'A', results, rawUsage });
}
writeFileSync(join(output, 'comparison.json'), JSON.stringify(runs, null, 2));
console.log('RESULT_DIR', output);
JS
node "$agent_compare_script"
```

В напечатанном `RESULT_DIR` сохраняются ответы, конфигурация без ключа, usage каждого хода и сырой provider usage (`rawUsage`). В каждой поддиректории — отдельная история и `results.json`; общий `comparison.json` содержит завершённые диалоги. При ошибке частичный результат не является сравнением полных диалогов.

Сопоставьте `usage.finalCall.promptTokens` на ходах 11, 12, 16, 17 и 20. Полный расход T — `usage.session.totalTokens` последнего хода (или сумма `usage.turn.totalTokens`), а стоимость сжатия — сумма ненулевых `usage.summaryCall.totalTokens`. Сессионные снимки разных ходов складывать нельзя. Экономия: `(T_A - T_B) / T_A × 100%`; T_B включает вход и выход обоих summary. Reasoning входит в completion и второй раз не добавляется. Если в `rawUsage` есть null или отсутствуют prompt/completion, измерение неполное: нулевой fallback агента не означает измеренный нулевой расход. Сокращение одного финального запроса само по себе не доказывает общую экономию.

### Результат 11 сентября 2026

Модель `deepseek-v4-flash`, настройки и последовательность — из блока выше. Два диалога по 20 ходов, 20 API-вызовов для A и 22 для B. Provider usage получен во всех 42 вызовах; reasoning=0.

| Расход токенов | A: без сжатия | B: со сжатием |
| --- | ---: | ---: |
| Вход всех вызовов | 17780 | 12332 |
| Генерация всех вызовов | 1387 | 1298 |
| **Всего** | **19167** | **13630** |
| Summary (входит в общий итог) | 0 | 1390 |

Первое summary: 476 входных + 127 выходных = 603 токена. Второе: 604 + 183 = 787 токенов.

| Ход | promptTokens финального вызова A | promptTokens финального вызова B |
| --- | ---: | ---: |
| 11 | 868 | 521 |
| 12 | 1066 | 681 |
| 16 | 1363 | 683 |
| 17 | 1600 | 869 |
| 20 | 1869 | 1084 |

По ручной проверке оба режима выполнили весь заранее заданный список на пяти контрольных ходах. Пропусков проверяемых фактов, противоречий, возврата бюджета 84000 или игнорирования решения о приёмке не обнаружено. На 11-м ходу приёмщик ещё не определён; на 16-м и 20-м — Павел Орлов. Ограничения хранения и сервисов соблюдены; недавние детали восстановлены.

Экономия полного расхода: `(19167 - 13630) / 19167 × 100% = 28,89%`. Это один прогон, не гарантия: ответы двух независимых запусков различались уже до первого сжатия при одинаковой температуре 0, а значит часть разницы связана с длиной ответов. Проверены конкретные факты этого сценария, не общая точность суммаризации. Денежная стоимость и влияние кеширования провайдера здесь не измерялись.

## Контракт агента

Публичная точка входа — `Agent.respond(input)`. Сырой ответ SDK, конфигурация и стек сообщений наружу не выдаются.

```ts
const agent = new Agent({ client: openai.chat.completions, config });
const result = await agent.respond("Меня зовут Максим");

console.log(result.text);
console.log(result.tokenEstimate);
console.log(result.usage.finalCall);
console.log(result.usage.turn);
console.log(result.usage.session);
```

`AgentConfig` содержит настройки одного агента:

- модель и системный промпт;
- стратегия `direct`, `steps`, `meta` или `experts`;
- формат `text`, `json`, `markdown` или `yaml`;
- лимит слов, лимит генерации `maxTokens` и локальный бюджет входа `maxInputTokens`;
- stop-маркер;
- температуру и thinking mode;
- включение сжатия `historyCompressionEnabled` и число последних сообщений `historyKeepLastMessages`.

Режимы сравнения нескольких конфигураций не входят в агент: это внешние сценарии над одним или несколькими экземплярами.

Без `historyRepository` агент хранит историю только в памяти. Необязательный `HistoryRepository` из `src/history.ts` предоставляет синхронные `load()` и `save()`; CLI передаёт `JsonHistoryRepository` из `src/json-history-repository.ts`. Путь к файлу не входит в `AgentConfig`.

История обновляется после непустого ответа и успешного сохранения. Ответ с `validation.ok === false` тоже завершает ход и сохраняется. Ошибка API, пустой ответ и незавершённая meta-стратегия не добавляют сообщений в контекст. Токены полученного, но пустого ответа учитываются, потому что API-вызов уже состоялся.

## Разработка

```bash
npm run lint
npm run typecheck
npm test
npm run test:coverage
npm run build
npm start
```

Тесты не обращаются к реальному API и пользовательской истории. Модульные тесты используют подставной LLM-клиент, а e2e-тесты запускают отдельные процессы с настоящим SDK и подменённым `fetch` во временных директориях. Mock проверяет восстановленные сообщения перед ответом; это не проверка ответа настоящей модели.

`npm install` подключает `.githooks/pre-commit`. CI выполняет линтер, проверку типов, тесты с порогами покрытия и сборку.
